01

컨셉

폐장 시간이 지난 지 오래지만 아무것도 멈추지 않았다. 관람차는 빈 곤돌라를 매단 채 계속 돌고, 회전목마는 아무도 요청하지 않은 오르골 루프에 맞춰 회전한다. 팝콘 기계는 아무도 비우지 않는 통에 계속 팝콘을 채운다. 플레이어는 정체를 알 수 없는 방문객으로서, 모든 디테일이 정확한데 딱 하나 — 어두워야 할 시간에 어둡지 않다는 점만 이상한 공간을 걷는다.

감정 목표: 공포가 아니라, 익숙한 것이 반 박자 어긋나 돌아가는 데서 오는 불편함. 플레이어가 "무서워"보다 "이상하게 평온한데, 뭔가 잘못됐어"에 더 가까이 도달해야 한다. 아무것도 쫓아오지 않는다. 아무것도 설명하지 않는다.

레퍼런스 DNA 백룸(공간적 위화감), The Pool(정지된 물리 기반 공허함), Placid Plastic Duck Simulator(오브젝트 장난감 놀이 자체가 루프 전체) — 물이나 복도 대신 야간 놀이공원을 축으로 재조합.
02

플랫폼 전략

최종 출시는 세 개 스토어를 동시에 겨냥한다. 각 스토어마다 "출시 가능"의 기준이 다르므로, 아래 계획은 이를 후순위로 두지 않고 역산해서 세웠다.

코드베이스 하나, 셸 세 개. 3D 씬·물리·오디오 로직은 한 번만 작성하고, 각 스토어는 입력 매핑·저장 데이터·스토어별 요구사항(개인정보 매니페스트, 필요 시 인앱결제 스텁, 스팀웍스 SDK 훅)을 담당하는 얇은 플랫폼 레이어만 추가로 갖는다.

03

클로드 코드 & 커서 기반 기술 실현성

클로드 코드와 커서는 텍스트/코드 중심 어시스턴트다. 프로젝트가 코드와 버전관리 파일로 표현될 때 강력하고, GUI 에디터 안에서 오브젝트를 드래그하는 워크플로우에는 관여할 수 없다 — 이는 언리얼이나 유니티의 자체 에디터를 주 워크플로우로 삼는 선택을 배제한다. 레벨 배치, 블루프린트, 머티리얼 그래프는 AI 어시스턴트가 의미 있게 편집할 수 있는 파일 밖에 존재하기 때문이다.

결정: 코드 중심 3D 웹 스택으로 만든 뒤 각 스토어에 맞게 래핑한다. 씬 그래프·물리·오디오·입력·절차적 배치 전부를 TypeScript로 유지해, 두 도구 모두 프로젝트 전체를 읽고 생성하고 리팩터링할 수 있게 한다.

레이어선택AI 협업 코드 전용 워크플로우에 맞는 이유
렌더러Three.js + React Three Fiber씬 구성이 JSX/TS — 별도 에디터 파일 없음
물리Rapier (@react-three/rapier)리지드바디·힘·콜라이더 전부 코드로 정의

오디오Howler.js + Web Audio API피치 워블(디튠 + LFO)이 플러그인 GUI가 아닌 스크립트
애니메이션 재생glTF 임포트 + Three.js AnimationMixer리깅은 블렌더에서 한 번, 재생 로직은 코드
절차적 배치시드 기반 RNG(seedrandom) + 스폰 포인트 배열순수 로직, AI가 전부 작성·테스트 가능
모바일 셸Capacitor같은 웹 빌드를 iOS/Android 네이티브 앱처럼 래핑
데스크톱 셸Electron같은 웹 빌드를 스팀 배포용으로 래핑
AI 협업 루프 밖에 남는 작업 3D 모델링/텍스처링(관람차, 회전목마, 매점)과 사운드 원본 녹음은 코드 문제가 아니다 — 블렌더 작업 또는 구매/라이선스 에셋(Kenney, Poly Haven, Sketchfab, Freesound)이 원재료로 필요하다. 이후 임포트, 재생 로직 연결, 물리 연동, 오디오 믹싱은 클로드 코드와 커서가 담당한다.

폴백 방안

WebView로 래핑된 Three.js 씬이 중저가 모바일 기기에서 허용 가능한 프레임률을 유지하지 못할 경우, 폴백은 Godot(GDScript/C#)이다. 여전히 스크립트 중심이라 코드 에디터에서 작업 가능하며, 유니티/언리얼보다 GUI 전용 작업의 비중이 훨씬 낮다. 이는 지금 내리는 결정이 아니라 프로토타입 단계 종료 시점의 체크포인트다.

04

핵심 게임플레이

이동 & 상호작용

  • 1인칭 걷기/가벼운 뛰기만 지원 — 전투, 점프 퍼즐, 실패 상태 없음.
  • 단일 상호작용 액션(E / 탭): 대상에 따라 밀기·잡기·타기로 자동 결정.
  • 잡은 오브젝트는 물리 핸드(하프라이프 스타일)를 따르며, 과도한 힘이나 충돌 시 놓침.
  • 퀘스트 로그 없음, 목표 마커 없음, 최소한의 조준점 외 HUD 없음.

절차적 변주

구역에 재진입할 때마다 세계 일부가 재시드된다: 소품 위치, 풍선 개수와 초기 드리프트, 켜진 조명, 앰비언트 오디오 루프가 크로스페이드되는 순서. 랜드마크·경로 같은 거시 구조는 고정되어, 공간이 매번 미묘하게 다르게 느껴지되 길을 잃지는 않는다.

탑승 가능; 카메라 고정, 흔들림 팔에 스웨이 물리 적용.
회전목마 목마
탑승 가능; 라이드 자체 애니메이션 루프와 동기화된 상하 진동.
잡동사니 소품
전단지, 컵, 티켓 — 일반 리지드바디, 바람과 충돌에 반응.
06

오디오 디자인

대사 없음. 사운드스케이프가 감정적 톤 전체를 담당한다.

  • 라이드 음악은 피치/속도 워블(대략 −5%~−10%, 느린 랜덤 LFO)을 거쳐 재생 — 이 공간의 불쾌한 골짜기 시그니처.
  • 레이어드 앰비언스: 모터 소음, 체인 덜컹임, 바람, 먼 곳의 물소리.
  • 거리 기반 3D 오디오: 플레이어가 각 라이드에 접근/이탈할 때 음악이 자연스럽게 크로스페이드.
07

레벨 구조 (v1)

하나로 연결된 맵, 3~4개의 보행 구역으로 분할:

  1. 정문 광장 — 매표소, 분수대, 시작 지점.
  2. 미드웨이 — 관람차, 회전목마, 유령의 집 외관.
  3. 먹거리 골목 — 팝콘·솜사탕 매점, 벤치, 쓰레기통.
  4. 백스테이지 (확장) — 직원 통로; 리미널 효과가 가장 짙어지는 구역.
08

내러티브 — 선택적, 설명하지 않음

파편만 존재한다: 벤치에 남겨진 메모, 벽 패널의 낙서, 매점 라디오에서 반복되는 정체불명의 방송. 수집 UI도, 도감도, 결말도 없다. 파편을 발견하는 행위 자체가 보상이며, 의미를 짜맞추는 일은 전적으로 플레이어의 몫이다.

성공 지표

  • 플레이테스터가 이 공간을 "무섭다"보다 "이상하다/어긋나 있다"로 더 자주 묘사하는지.
  • 세션당 구역 재진입 평균 횟수(절차적 변주가 실제로 인지되고 재방문을 유도하는지).
  • 물리 장난감(풍선, 팝콘)과의 상호작용 빈도 — 오브젝트 놀이가 실제 훅인지 확인.
  • 지원 최저 사양 모바일 기기의 프레임타임 안정성 — 플랫폼 동시 배포 전략의 게이팅 지표.
